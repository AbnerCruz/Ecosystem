## Pergunta

Qual desenho deve virar a Host API pública usada pelos Product Shells antes de escolher o transporte IPC?

## Alternativas no momento da escolha

A. **A — Host API semântica e neutra de transporte (recomendada)** ← escolhida
   Congela operações/invariantes de sessão, discovery, Context, identidade, grants, execução, cancelamento, revogação e erros sem escolher wire protocol. Reutiliza contratos da Fase 2; ecosystem-local/0 continua experimental; P5-4 escolhe transporte e autenticação depois.

B. **B — Promover ecosystem-local/0 como API pública**
   Menor mudança imediata no Hub, mas congela detalhes do primeiro experimento sem segundo Host real e aumenta o risco de uma API supostamente genérica ser, na prática, a implementação do Hub.

C. **C — Definir primeiro o IPC e tratá-lo como Host API**
   Une semântica pública e transporte numa única decisão; antecipa socket/serviço/autenticação e dificulta bindings em processo e multiplataforma. Inverte a sequência P5-3 → P5-4.
