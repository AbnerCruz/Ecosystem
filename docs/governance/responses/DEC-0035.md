## Pergunta

Qual pilha deve implementar UI e hosts do novo Urbe C# em Web/PWA, Windows e Android?

## Alternativas no momento da escolha

A. **A — Blazor WebAssembly PWA no Web + .NET MAUI Blazor Hybrid em Windows/Android, com UI compartilhada em Razor Class Library (recomendada)** ← escolhida
   Core C# puro e a maior parte da UI compartilhada; DOM real preserva o caminho de menor risco para editor, IME, teclado móvel e acessibilidade; PWA continua estática/offline; hosts MAUI fornecem capacidades nativas por interfaces. Aceita WebView nos hosts nativos e adapters mínimos de browser quando não existir API .NET equivalente. Nenhuma lógica canônica do Urbe fica em JavaScript.

B. **B — Avalonia 12 como UI C#/XAML única em Windows, Android e WebAssembly**
   Uma única árvore visual e bom desenho 2D. Em troca, o editor deixa de aproveitar diretamente o DOM e o suporte IME em WebAssembly é oficialmente parcial; exige prova forte de teclado/seleção/acessibilidade/PWA antes de adotar.

C. **C — Uno Platform como UI C#/XAML única em Windows, Android e WebAssembly**
   Alta reutilização e targets declarados para as três superfícies. Introduz uma dependência estrutural adicional e exige spikes do editor, PWA/offline, storage legado e mundo 2D antes de qualquer confiança em paridade.

D. **D — UI separada por superfície: Blazor WebAssembly no Web e UI nativa C# distinta em Windows/Android, compartilhando apenas Core**
   Maior liberdade por host e melhor acesso aos recursos específicos, mas duplica UI e testes e aumenta muito o risco/custo de manter editor e mundo semanticamente idênticos.
