## Pergunta

Como as instalações existentes devem migrar do cliente JavaScript para o cliente C# quando G-C5 autorizar o corte?

## Alternativas no momento da escolha

A. **A — Ponte preservando identidade/origem, com rollout por superfície somente após G-C5 (recomendada)**
   Android mantém app.urbe, a mesma chave privada e versão crescente; Windows recebe uma ponte explícita do updater/instalador para o novo cliente e preserva o vault; Web troca a implementação primeiro na mesma origem/escopo para manter IndexedDB/PWA. Canais antigos ficam como recuperação. Mover para plataforma first-party/origem nova vira migração separada.

B. **B — Cliente C# paralelo com identidades/canais próprios e migração explícita de vault**
   Evita updater cruzando tecnologias e facilita rollback por coexistência, mas duplica aplicativos/configurações e cria uma segunda identidade do mesmo Product; no Web uma origem nova não enxerga automaticamente o IndexedDB antigo.

C. **C — Reinstalação deliberada com backup/export/import obrigatório** ← escolhida
   Simplifica o mecanismo técnico: remover cliente antigo, instalar o novo e importar. Sacrifica continuidade, aumenta atrito e risco humano e não atende bem à expectativa normal de atualização.

D. **D — Big-bang simultâneo nas três superfícies preservando identidade**
   Uma única data de corte, mas blast radius máximo: um problema em Android, Windows ou PWA bloqueia ou força rollback coordenado das três superfícies.
